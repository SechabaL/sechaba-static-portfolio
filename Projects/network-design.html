Enterprise Network Segmentation.

01 / Overview

Establishing logical boundaries within an enterprise network.

Enterprise networks require an organised approach to connecting devices, services and operational departments. A flat network architecture can place unrelated devices within the same broadcast domain, creating unnecessary traffic and limiting the ability to manage communication between different network segments.

This project addresses that architectural concern through Virtual Local Area Network (VLAN) segmentation. The topology was implemented in Cisco Packet Tracer to demonstrate how logical network boundaries can be established within a shared network infrastructure.

The implementation focuses on separating departmental network segments, improving network organisation and establishing a foundation for controlled inter-segment communication.

02 / Engineering Context

Why network segmentation matters.

Network segmentation is an architectural approach to dividing a larger Layer 2 network into smaller logical broadcast domains. VLANs provide a mechanism for implementing this separation without requiring every department to operate on physically independent infrastructure.

01

Traffic Isolation

VLANs establish separate broadcast domains, limiting the propagation of Layer 2 broadcast traffic to the relevant logical segment.

02

Network Organisation

Logical grouping allows devices to be organised according to departmental or operational requirements rather than physical location alone.

03

Controlled Communication

Logical separation provides a basis for managing communication between network segments through appropriate Layer 3 routing and access-control mechanisms.

03 / Implementation

From network design to simulation.

Logical Network Separation

The topology applies VLAN segmentation to organise connected devices into distinct logical network segments. This provides separation at the switching layer and establishes a more structured network design.

Simulation Environment

Cisco Packet Tracer was used as the network simulation environment. The resulting topology is preserved in a native Packet Tracer project file, allowing the network arrangement to be inspected and opened independently.

Technical Documentation

The project is accompanied by a dedicated technical document and a GitHub repository containing the project artefacts. This separates the implementation itself from its supporting documentation and makes the work independently accessible.

05 / Engineering Perspective

Understanding the infrastructure beneath connectivity.

This project provided practical exposure to the relationship between logical network architecture, switching infrastructure and traffic separation. It reinforced the importance of designing networks around operational boundaries rather than treating connectivity as a matter of simply linking devices.

The work also forms part of a broader interest in network and infrastructure engineering: understanding how infrastructure is structured, how communication is governed and how network environments can be designed for manageability and operational control.
